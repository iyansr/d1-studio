# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`@iyansr/d1-studio`: a zero-config CLI (`d1-studio --local | --remote`) that starts a local Hono server and serves a prebuilt React UI for browsing and editing Cloudflare D1 databases. It reads the project's existing Wrangler config and credentials. Spec: `docs/PRD.md`. Plans per milestone, verified facts, and the decision log (D1–D13): `docs/plans/README.md`. Read the relevant plan before working on a feature; each plan ends with a status/deviations section.

## Commands

pnpm workspace: root package (published CLI) + `ui/` (private Vite app).

```bash
pnpm dev [project-dir] [cli flags…]   # tsup --watch CLI + Vite with /api proxy; defaults to e2e/fixtures/project. Open the `dev` link from the banner.
pnpm build                            # build:ui (Vite -> dist/ui) then build:cli (tsup -> dist/cli.js)
pnpm check                            # lint (incl. type check) + format check + unit tests; must pass before each commit
pnpm lint                             # oxlint, type-aware with TS diagnostics (replaces tsc)
pnpm format                           # oxfmt (sorts imports, Tailwind classes, package.json) + oxlint --fix
pnpm test                             # vitest unit/integration (test/**, excludes smoke + live)
pnpm vitest run test/sql/limit.test.ts          # single file
pnpm vitest run -t "name of test"               # single test by name
pnpm test:smoke                       # against built dist/cli.js (build first)
pnpm test:e2e                         # Playwright against built dist/cli.js (build first)
pnpm exec playwright test e2e/editing.spec.ts   # single e2e file
pnpm test:live                        # real D1 API; needs D1S_LIVE_TOKEN and D1S_LIVE_ACCOUNT
pnpm check:size                       # bundle size budget
```

Test fixtures (SQLite files under `.wrangler/state`) are generated by vitest/Playwright global setup (`test/fixtures/make.ts`, `e2e/fixtures/make.ts`); `pnpm fixtures` regenerates them manually.

CI runs `pnpm check`, build, size and smoke on Ubuntu/macOS/Windows × Node 22/24, plus Playwright and a Bun job. Node `>=22.16` (uses `node:sqlite`; `bun:sqlite` under Bun).

## Architecture

```
src/cli/      args, port resolution, prompts, banner, browser open; main() wires config -> driver -> server
src/config/   find wrangler.json -> .jsonc -> .toml (walk up, honours .wrangler/deploy/config.json redirect), parse, select env/binding
src/local/    Miniflare .sqlite filename derivation (HMAC of preview_database_id ?? database_id ?? binding), candidate scan, sqlite adapter
src/remote/   credentials chain (CLOUDFLARE_API_TOKEN, else `wrangler auth token` from the project's Wrangler), D1 REST client
src/drivers/  Driver interface; LocalDriver/RemoteDriver implement only query + batch; introspect.ts is shared PRAGMA-based introspection
src/sql/      PURE, security-critical: tokenizer, splitter, classifier (read-only allow-list), auto-limit, ident quoting, rows-query builder, edit-op compiler
src/server/   createApp(ctx) Hono factory (no globals), security middleware, routes under /api, static UI
src/shared/   API + value types imported by both server and UI (`@shared` alias in ui)
ui/src/       React + shadcn/ui (Tailwind v4, Base UI). Custom: grid/ (TanStack Table + Virtual), editor/ (CodeMirror), edits/ (staged grid changes)
```

Key cross-cutting points:

- **Typed RPC, no DTOs.** UI calls the server with Hono's `hc<AppType>` (`ui/src/lib/api.ts` imports `AppType` from `src/server/app.ts`). Route changes flow types to the UI; keep route definitions chained so types are inferred.
- **Server is testable without a port.** `createApp(ctx)` takes an `AppContext`; server tests use `test/server/harness.ts` and `app.request()`. Remote is tested against a fake D1 API (`test/remote/fake-d1.ts`, `test/fixtures/d1-api/`). Remote-write e2e specs start `createApp` in-process over the fake API rather than hooking the shipped CLI.
- **Errors.** Typed errors (`DbError`/`BatchError`/`ConflictError`, `RowsQueryError`, `EditError`, `D1ApiError`, `UnknownIdentifierError`) are mapped to HTTP in `createApp`'s `onError`; envelope is `{ error: { message, code?, statementIndex?, opIndex?, preview? } }`. Engine messages are shown verbatim. Never pass an upstream 401 through (UI treats 401 as lost session).
- **Read-only / write safety.** Read-only is default; `--write` enables edits. `server/read-only.ts` enforces via the `sql/classify` allow-list (the only guard for remote). Remote writes require confirmation; DROP, `ALTER … DROP`, and UPDATE/DELETE without WHERE require typing the database name (`server/confirm.ts`).
- **Grid edits are structured ops**, not SQL (D6): UI sends `update`/`insert`/`delete` + row key to `/api/batch`; server compiles them (`sql/edits.ts`), `?dryRun=1` returns exact SQL for the confirm dialog. `expectChanges` detects conflicts (409, rolled back).
- **Value encoding over JSON:** rows are arrays with a separate `columns` array (keeps duplicate names). Integers beyond ±2^53 are `{ "$int": "…" }`; BLOBs are `{ "$blob": byteLength }`.
- **Session security.** Random token passed once as `/?t=…`, then cookie `d1s_<port>` (D8). Host allow-list blocks DNS rebinding. The Cloudflare token and session token must never reach logs, errors or the browser (`test/remote/token-leak.test.ts`).
- **Remote cost.** D1 bills per row read: remote row counts load lazily and are cached per session (D9); the count cache is patched from batch inserts/deletes.
- **Bundling.** All runtime deps are bundled into `dist/cli.js` (`dependencies` stays `{}`, D7); only `node:sqlite`/`bun:sqlite` are external. Put new runtime libs in `devDependencies`.

## Conventions

- ESM, strict TS. oxfmt: 2-space, 100 cols, single quotes in TS, double quotes for JSX attributes and CSS. oxlint (`.oxlintrc.json`) and oxfmt (`.oxfmtrc.json`) ignore `ui/src/components/ui/` and `docs/`; oxfmt also skips the JSON fixtures. Suppress with `// oxlint-disable-next-line <rule> -- reason`.
- shadcn rules: use an existing shadcn component before custom markup (`Alert`, `Empty`, `Skeleton`, sonner, `Badge`); semantic tokens only, no raw colours or manual `dark:`; `gap-*` not `space-*`; `size-*` for equal w/h; button icons use `data-icon` with no sizing classes. Add/update components only via `pnpm dlx shadcn@latest add` (run from `ui/`, `--diff` before updating); never hand-edit `components/ui/`.
- Commits: Conventional Commits, one per plan task, tagged with the task id, e.g. `feat(ui): … (04-T6)`. Record status and deviations in the plan's Status section.
